# 가계부 앱 PRD (Product Requirements Document)

- 문서 버전: 1.0 (사용자 승인 완료)
- 작성일: 2026-10-26
- 범위: "무엇을 만들 것인가". 구현 방법·폴더 구조는 `docs/DEVELOPMENT_PLAN.md`(2단계)에서 다룬다.

---

## 1. 제품 목표와 사용자 정의

### 1.1 제품 목표
- 수입과 지출을 빠르게 기록하고, 월 단위로 돈의 흐름(수입·지출·잔액·카테고리별 비중)을 한눈에 파악하게 한다.
- 계정·서버 없이 브라우저만으로 바로 쓸 수 있는 가볍고 빠른 가계부를 만든다.
- 데이터 구조는 향후 **가족 공동 사용**과 **서버 저장(SQLite/Supabase 등)** 으로 확장 가능하게 설계한다. 단, MVP에서는 구현하지 않는다.

### 1.2 사용자 정의
| 구분 | 설명 |
| --- | --- |
| 1차 사용자 | 개인 1인. 월 단위로 소비를 점검하고 싶은 일반 사용자 |
| 향후 사용자 | 가족 구성원(공동 가계부). MVP에서는 1인 데이터만 입력하되, 데이터에 "소유자(구성원)" 개념을 미리 반영한다 |
| 환경 | PC·모바일 브라우저. 한국어 사용자, 통화는 원화(KRW) 고정 |

### 1.3 설계 원칙
- 입력은 최소 클릭으로 끝낸다 (자주 쓰는 값 기본 선택).
- 숫자는 항상 정확해야 한다 (정수 원 단위).
- 데이터는 사용자 소유다 (로컬 저장 + JSON 백업).

## 2. 핵심 사용자 여정

1. **첫 진입**: 앱을 열면 이번 달 요약과 빈 내역 안내가 보이고, 기본 카테고리·결제수단이 준비되어 있다.
2. **내역 등록**: "추가" → 지출/수입 선택 → 금액·날짜·카테고리·결제수단·메모·태그 입력 → 저장 → 목록과 요약이 즉시 갱신된다.
3. **월별 확인**: 상단 월 이동으로 지난달/다음 달을 조회하고 수입·지출·잔액을 비교한다.
4. **분석**: 카테고리별 지출 집계(도넛 차트)와 최근 6개월 추이를 본다.
5. **탐색**: 검색어·필터(유형, 카테고리, 결제수단, 태그)로 특정 내역을 찾는다.
6. **수정/삭제**: 내역을 선택해 수정하거나 삭제한다(삭제 시 확인).
7. **관리**: 카테고리를 추가·수정·삭제하고, 데이터를 JSON으로 내보내거나 가져와 백업·복원한다.
8. **재방문**: 새로고침·재접속 후에도 데이터가 유지된다.

## 3. MVP 기능 범위

### 3.1 거래 내역
- 지출/수입 내역 등록, 수정, 삭제
- 입력 항목: 날짜, 금액, 유형(지출/수입), 카테고리, 결제수단, 메모, 태그
- 입력값 검증 (금액 > 0 정수, 날짜 필수, 카테고리 필수 등)

### 3.2 요약·집계
- 월별 수입 합계, 지출 합계, 잔액(수입 − 지출)
- 카테고리별 지출 집계 (금액, 비율)
- 도넛 차트(카테고리별 지출 비중), 최근 6개월 수입·지출 추이 차트

### 3.3 조회
- 최근 내역 목록 (날짜 내림차순, 날짜별 그룹)
- 검색(메모·태그·카테고리명 텍스트) 및 필터(유형, 카테고리, 결제수단, 태그)
- 월 이동(이전/다음/이번 달) 및 월별 조회

### 3.4 설정·관리
- 카테고리 관리 화면: 기본 카테고리 제공 + 사용자 추가/수정/삭제
- 결제수단은 기본 목록 제공(MVP에서는 고정 목록, 관리 화면은 향후)
- JSON 내보내기·가져오기(백업/복원)
- 다크 모드(시스템 설정 따름 + 수동 전환)

### 3.5 저장
- localStorage 기반 저장. 저장소 계층을 인터페이스로 추상화해 이후 다른 저장소로 교체 가능하게 한다.

## 6. 데이터 모델 초안

> 모든 엔티티는 `id`(고유 문자열), `createdAt`, `updatedAt`을 가진다. 금액은 **정수 원**. 날짜는 시간대 없는 로컬 날짜 문자열(`YYYY-MM-DD`)로 다룬다.

### Transaction (거래)
| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | string | 고유 ID |
| type | `'expense' \| 'income'` | 지출/수입 |
| amount | integer | 원 단위 양의 정수 (부호는 type으로 표현) |
| date | string (`YYYY-MM-DD`) | 거래 일자 |
| categoryId | string | Category 참조 |
| paymentMethodId | string | PaymentMethod 참조 (수입도 입금 수단으로 사용 가능) |
| memo | string | 선택, 최대 길이 제한 |
| tags | string[] | 선택, 정규화(공백 제거·중복 제거) |
| ownerId | string | 소유 구성원. MVP에서는 기본 구성원 1명 고정 (공동 사용 대비) |
| createdAt / updatedAt | ISO string | 생성/수정 시각 |

### Category (카테고리)
| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | string | |
| name | string | 이름 (동일 유형 내 중복 불가) |
| type | `'expense' \| 'income'` | 적용 유형 |
| color | string | 차트 표시용 색상 |
| isDefault | boolean | 기본 제공 여부 |
| sortOrder | number | 표시 순서 |

### PaymentMethod (결제수단)
| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | string | |
| name | string | 예: 현금, 체크카드, 신용카드, 계좌이체, 기타 |
| sortOrder | number | |

### Member (구성원) — 공동 사용 대비
| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | string | |
| name | string | MVP에서는 기본 1명 ("나") |

### AppSettings (설정)
| 필드 | 타입 | 설명 |
| --- | --- | --- |
| theme | `'system' \| 'light' \| 'dark'` | |
| schemaVersion | number | 데이터 마이그레이션용 |

### 백업 파일(JSON) 형식
- `{ schemaVersion, exportedAt, members, categories, paymentMethods, transactions, settings }`
- 가져오기 시 스키마 검증 후 적용, 잘못된 파일은 거부하고 기존 데이터를 보존한다.

### 기본 데이터(초안)

- 결제수단: 현금, 체크카드, 신용카드, 계좌이체, 기타

## 7. 주요 비즈니스 규칙

1. **금액**: 1 이상의 정수 원. 소수점·음수·0·비숫자 입력 불가. 합계·비율 계산은 정수 기반으로 하며 부동소수점 오차가 없어야 한다. 허용 최대값을 둔다(예: 100억 원 미만).
2. **잔액** = 해당 월 수입 합계 − 지출 합계 (음수 가능, 음수는 시각적으로 구분).
3. **날짜**: 로컬 타임존 기준. 월 경계(말일/1일, 윤년)에서 다른 달로 잘못 집계되지 않아야 한다. 월 조회는 `YYYY-MM` 기준이다.
4. **카테고리 집계**: 지출 거래만 대상으로 하며, 비율은 합이 100%가 되도록 반올림 규칙을 정한다.
5. **카테고리 삭제**: 사용 중인 카테고리를 삭제하려면 거래를 다른 카테고리로 재배정하거나 삭제를 막는다(안내 필수). 기본 카테고리도 삭제할 수 있으나 유형별 '기타' 카테고리는 삭제할 수 없다(확정).
6. **카테고리 이름**: 동일 유형 내 중복 불가, 공백만으로 구성 불가.
7. **태그**: 앞뒤 공백 제거, 대소문자 구분 없이 중복 제거, `#` 접두는 저장 시 제거.
8. **검색**: 메모·태그·카테고리명을 대소문자 구분 없이 부분 일치로 검색한다. 필터는 AND 조건이다. 검색·필터는 현재 선택한 월 범위 안에서 동작한다(전체 기간 검색은 향후 확장).
9. **삭제**: 거래 삭제는 확인 단계를 거친다.
10. **가져오기**: 기존 데이터를 덮어쓰기 전에 사용자 확인을 받는다. 검증 실패 시 기존 데이터는 변경하지 않는다.
11. **초기화**: 전체 데이터 초기화는 확인을 받고, 이후 기본 카테고리·결제수단이 복원된다.
12. **미래 날짜**: 입력 가능(예정 지출 기록 허용), 별도 제한 없음.

## 8. 비기능 요구사항

- **성능**: 월 1,000건, 전체 수만 건 규모에서도 목록·집계가 체감 지연 없이 동작(초기 로드 2초 이내 목표).
- **저장 안정성**: 저장 실패(용량 초과, 접근 차단)와 손상된 데이터에 대한 오류 처리 및 사용자 안내. 스키마 버전 기반 마이그레이션.
- **확장성**: 저장소 추상화로 SQLite/Supabase 등 교체 가능. 거래에 `ownerId`를 두어 공동 사용 확장에 대비.
- **반응형**: 모바일(360px~)·태블릿·데스크톱 지원, 가로 스크롤 없음.
- **접근성**: 키보드 조작 가능, 폼 라벨·오류 메시지 연결, 충분한 색 대비(라이트/다크 모두), 차트는 색 외 수치 텍스트로도 정보 제공(WCAG 2.1 AA 지향).
- **보안·프라이버시**: 데이터는 사용자 브라우저 밖으로 전송하지 않음. 외부 추적·분석 도구 없음. 소스·문서에 실제 금융 데이터나 키를 포함하지 않음. 입력값은 안전하게 렌더링(XSS 방지).
- **브라우저**: 최신 Chrome, Edge, Safari, Firefox.
- **품질**: 타입 안정성(TypeScript strict), 단위 테스트와 Playwright E2E로 주요 흐름 검증.
- **현지화**: 한국어 UI, 원화 표기(예: `12,000원`), 한국 요일·날짜 표기.

## 9. 성공 기준

**기능**
- 지출·수입 등록, 수정, 삭제가 모두 동작하고 새로고침 후에도 유지된다.
- 월 요약(수입·지출·잔액)과 카테고리 집계가 입력 데이터와 정확히 일치한다.
- 검색·필터·월 이동이 정상 동작한다.
- 카테고리 관리와 JSON 내보내기→가져오기 왕복(roundtrip) 시 데이터가 동일하다.
- 다크 모드가 모든 화면에서 깨지지 않고 표시된다.

**품질**
- Critical/High 이슈 0건.
- 타입 검사·린트·단위 테스트·Playwright E2E 전부 통과.
- 모바일(예: 390px)·데스크톱 화면에서 레이아웃 깨짐 없음.

**사용성**
- 첫 진입 후 거래 1건 등록까지 1분 이내, 입력 필드 외 불필요한 단계 없음.

## 10. 리스크 및 향후 확장 계획

### 리스크
| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| localStorage 데이터 유실(브라우저 데이터 삭제) | 높음 | JSON 백업 제공, 설정 화면에서 백업 권장 안내 |
| localStorage 용량 한계(약 5MB) | 중간 | 저장 크기 모니터링, 저장소 추상화로 IndexedDB/서버 교체 대비 |
| 날짜·타임존 버그(월 경계 집계 오류) | 높음 | 날짜 문자열 기반 처리, 경계 단위 테스트 |
| 금액 계산 오차 | 높음 | 정수 원 단위, 비율 반올림 규칙 명시 |
| 공동 사용 확장 시 데이터 구조 변경 | 중간 | `ownerId`·`Member`·`schemaVersion` 선반영 |
| 범위 확대(MVP 비대화) | 중간 | 제외 기능 목록 유지, 단계별 승인 |
