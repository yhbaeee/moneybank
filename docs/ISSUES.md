## 상세

### ISS-001 카테고리 화면에서 "설정" 메뉴 비활성 (단계 2)
- 원인: `NavLink`가 자체 계산한 `aria-current`로 덮어써 하위 경로(`/categories`)를 활성으로 표시하지 못함.
- 해결: `Link` + 직접 계산한 `aria-current`로 교체. 검증: `layout.spec.ts`(화면 간 이동).

### ISS-002 모바일 "내역 추가" 중복 (단계 4)
- 원인: `Button`의 `inline-flex`가 `hidden`을 덮어씀(Tailwind 유틸리티 충돌) → 모바일에서 페이지 버튼과 FAB가 모두 보임.
- 해결: 버튼을 `hidden md:block` 컨테이너로 감싸 숨김. 규칙을 `CLAUDE.md`에 기록. 검증: `transactions.spec.ts` 모바일 프로젝트.

### ISS-003 월 기준 목록 전환 후 테스트 실패 (단계 6)
- 원인: 앱 결함이 아니라 테스트가 실제 시계("오늘")와 이전 빈 상태 문구에 의존.
- 해결: 오늘 고정(`fixToday`, `vi.useFakeTimers({ toFake: ['Date'] })`), 문구 갱신. 테스트를 삭제·건너뛰지 않음.

### ISS-004 추이 차트 과대 확대 (단계 7)
- 원인: SVG가 컨테이너 폭(데스크톱 ~1000px)에 맞춰 viewBox가 확대되어 글자·막대가 커짐.
- 해결: `max-w-lg`로 폭 제한.

#### 테스트 작성 중 발견한 테스트 쪽 문제 (앱 결함 아님)
- 대상 크기 테스트가 화면이 그려지기 전에 측정해 간헐적으로 통과(거짓 양성) → 요소가 보일 때까지 대기하도록 수정하고 `--repeat-each`로 재확인.
- "Tab이 대화상자 밖으로 나가지 않는다"는 기대가 네이티브 `<dialog>` 동작(끝에서 브라우저 UI로 이동)과 달라 → "뒤쪽 페이지 요소로 새지 않는다"로 정정.
- App 테스트 간 주소(URL)가 이어져 후속 테스트 실패 → 각 테스트 전에 `/`로 초기화.

### 단계 9
- 카테고리 관리·백업·초기화 구현 중 앱 결함은 발견되지 않았다(axe 위반 0건, E2E 전부 통과). 신규 이슈 없음.
- 알려진 한계: 카테고리가 9개를 넘으면 차트 색이 반복된다(팔레트 9색). 필요하면 색 선택지 확장.

### ISS-015 Firefox E2E 접속 거부 (단계 10)
- 증상: Firefox/WebKit 프로젝트 추가 후 Firefox의 일부 테스트가 `page.goto: NS_ERROR_CONNECTION_REFUSED`로 간헐 실패(앱 결함 아님).
- 원인: 개발 서버가 환경에 따라 `localhost`를 IPv6(`::1`)로만 열고, Firefox는 IPv4(`127.0.0.1`)로 접속을 시도해 거부됨. Chromium은 자동으로 대체 주소를 시도해 드러나지 않았음.
- 해결: `playwright.config.ts`에서 서버를 `--host 127.0.0.1`로 열고 `baseURL`도 같은 주소로 고정. 검증: 교차 브라우저 핵심 흐름 75건 통과, 이후 반복 실행에서도 재현되지 않음.

### ISS-016 테스트 공백 4건 (단계 10, 변이 점검에서 발견)
앱 결함이 아니라 **버그가 있어도 통과해 버리는 테스트**였다. 핵심 로직에 일부러 버그를 넣는 변이 점검(32건) 중 4건이 살아남아 발견했고, 모두 테스트를 보강해 검출되도록 했다.
| 살아남은 변이 | 원인 | 보강 |
| --- | --- | --- |
| 11월을 31일로 취급 | 월별 일수를 일부 달만 검사 | 12개월 × 평년/윤년 전수, 마지막 날과 다음 날 검증 |
| 비율 동률 처리 제거 | 기존 동률 케이스가 변이 유무와 결과가 같았음(약한 테스트) | 브루트포스로 구분되는 케이스(`[5, 11]`, `[7, 9]`, `[1, 1, 10]`)로 교체 |
| 차트 막대 위치(y) 오류 | 높이만 측정 | 모든 막대 바닥이 같은 기준선인지 단위·E2E 검증 |
| 유형 변경 시 카테고리 미초기화 | 기존 테스트가 카테고리를 매번 직접 선택해 버그를 가림 | 카테고리를 건드리지 않고 저장하는 단위·E2E 시나리오 추가 |

### ISS-017 병렬 실행 시 E2E 간헐 실패 (단계 10)
- 증상: 전체 E2E를 기본 워커(8개)로 5회 연속 실행했을 때 412/418(6건 실패), 418, 417, 418, 417로 **결과가 들쭉날쭉**. 워커 1개·2개는 418건 모두 통과 → 병렬·부하에서만 발생.
- 원인(세 가지가 겹쳐 있었다):
  1. **의존성 재번들로 인한 페이지 새로고침**: 의존성이 바뀐 직후 첫 실행에서 Vite 개발 서버가 실행 중 새 의존성을 발견해 페이지를 새로고침 → 여러 테스트에서 동시에 `Execution context was destroyed`/타임아웃(1회차 6건).
  2. **일시적인 알림에 의존한 단언**: 알림(토스트)이 4초 뒤 사라지는데, 테스트가 느린 다운로드 파일 읽기 **뒤에** 알림을 확인(Firefox 백업 테스트). 또한 알림 확인을 클릭 **전에** 시작하면 클릭이 느릴 때 확인이 먼저 시간 초과됨.
  3. **자원 고갈**: 코어 수(16)만큼 워커를 늘리면(기본의 2배) Firefox/WebKit이 `page.goto`까지 30초를 넘기는 시간 초과가 발생. 앱·테스트 결함이 아닌 과부하.
- 해결:
  1. `vite.config.ts`의 `optimizeDeps.include`로 react·react-dom·react-router-dom을 서버 시작 시 미리 번들.
  2. 백업 E2E: 공용 헬퍼(`exportBackup`)는 알림에 의존하지 않게 하고, 알림 확인은 그것이 주제인 테스트 한 곳에서 클릭 **직후** 수행. 알림 표시 시간은 성공 6초·오류 10초로 연장(WCAG 2.2.1 시간 조절 측면에서도 4초는 짧았음, 단위 테스트 추가).
  3. 워커 수를 코어 수 이상으로 올리지 않는다(`docs/TESTING.md`에 명시). 기본값(코어의 절반)은 안정적임을 확인.
- 검증: 수정 후 기본 워커 전체 E2E **연속 7회(418건씩) 전부 통과**(워커 2개 1회 포함 통과), 교차 브라우저 핵심 흐름 부하 반복(26개 × 3 엔진 × 6회 = 468건) 전부 통과.
- 한계: 워커 16개 + Firefox/WebKit 집중 실행 같은 극단적 과부하에서는 여전히 시간 초과가 날 수 있다(테스트 재시도로 가리지 않음).
