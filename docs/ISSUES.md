## 상세

### ISS-001 카테고리 화면에서 "설정" 메뉴 비활성 (단계 2)
- 원인: `NavLink`가 자체 계산한 `aria-current`로 덮어써 하위 경로(`/categories`)를 활성으로 표시하지 못함.
- 해결: `Link` + 직접 계산한 `aria-current`로 교체. 검증: `layout.spec.ts`(화면 간 이동).

### ISS-002 모바일 "내역 추가" 중복 (단계 4)
- 원인: `Button`의 `inline-flex`가 `hidden`을 덮어씀(Tailwind 유틸리티 충돌) → 모바일에서 페이지 버튼과 FAB가 모두 보임.
- 해결: 버튼을 `hidden md:block` 컨테이너로 감싸 숨김. 규칙을 `CLAUDE.md`에 기록. 검증: `transactions.spec.ts` 모바일 프로젝트.

### ISS-003 월 기준 목록 전환 후 테스트 실패 (단계 6)
- 원인: 앱 결함이 아니라 테스트가 실제 시계("오늘")와 이전 빈 상태 문구에 의존.
- 해결: 오늘 고정(`fixToday`, `vi.useFakeTimers({ toFake: ['Date'] })`), 문구 갱신. 테스트를 삭제·건너뛰지 않음.

### ISS-004 추이 차트 과대 확대 (단계 7)
- 원인: SVG가 컨테이너 폭(데스크톱 ~1000px)에 맞춰 viewBox가 확대되어 글자·막대가 커짐.
- 해결: `max-w-lg`로 폭 제한.

axe(WCAG 2.0/2.1 A·AA) 기준선은 위반 0건이었으나, 자동 검사가 잡지 못하는 항목을 Playwright 동작 테스트(`a11y-behavior.spec.ts`)로 검증해 아래를 발견·해결했다.

#### 테스트 작성 중 발견한 테스트 쪽 문제 (앱 결함 아님)
- 대상 크기 테스트가 화면이 그려지기 전에 측정해 간헐적으로 통과(거짓 양성) → 요소가 보일 때까지 대기하도록 수정하고 `--repeat-each`로 재확인.
- "Tab이 대화상자 밖으로 나가지 않는다"는 기대가 네이티브 `<dialog>` 동작(끝에서 브라우저 UI로 이동)과 달라 → "뒤쪽 페이지 요소로 새지 않는다"로 정정.
- App 테스트 간 주소(URL)가 이어져 후속 테스트 실패 → 각 테스트 전에 `/`로 초기화.

### 단계 9
- 카테고리 관리·백업·초기화 구현 중 앱 결함은 발견되지 않았다(axe 위반 0건, E2E 전부 통과). 신규 이슈 없음.
- 알려진 한계: 카테고리가 9개를 넘으면 차트 색이 반복된다(팔레트 9색). 필요하면 색 선택지 확장.
