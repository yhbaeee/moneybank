## 5. 알려진 한계 (MVP 이후 과제)

1. **저장 용량**: 브라우저 localStorage(약 5MB) 한도 — 내역 1건 약 260자 기준 **Chrome·Edge·Firefox 약 2만 건, Safari(iOS 포함) 약 1만 건**(한글 데이터를 2바이트로 세어 절반). 사용률 표시·80% 경고·백업 권장으로 대응했으며, 근본 대책은 저장소를 IndexedDB 등으로 교체하는 것(인터페이스 덕분에 UI 변경 없이 가능).
2. **데이터 위치**: 데이터는 이 브라우저에만 있다(기기 간 동기화 없음). 백업 파일로 옮긴다.
3. **임시 저장 모드**: 브라우저 저장소를 막은 환경(시크릿 등)에서는 창을 닫으면 데이터가 사라진다(경고 배너로 항상 안내).
4. **카테고리 색**: 9색 팔레트라 9개를 넘으면 차트에서 색이 반복된다. 순서 변경 기능 없음.
5. **검색**: 선택한 월 범위 안에서만 동작(전체 기간 검색은 향후).
6. **교차 브라우저 테스트**: Firefox·WebKit은 핵심 흐름만 자동 검증(전체는 Chromium).
7. **수동 확인이 필요한 것**: 실제 스크린리더 읽기 순서, 브라우저 200% 확대, 실제 기기 터치, 거래 1건 등록 소요 시간.
8. **E2E 부하 한계**: 워커 수를 코어 수 이상으로 올리면(과부하) Firefox/WebKit이 시간 초과할 수 있다(`docs/TESTING.md`).
9. **오류 경계**: 단위 테스트로만 검증(E2E에서 렌더 오류를 안전하게 일으킬 방법이 없음).

## 6. 향후 확장 (PRD 10절 기준)

서버 저장·로그인·기기 간 동기화 / 가족 공동 사용(구성원 초대, 구성원별 보기) / CSV 가져오기·내보내기 / 예산·반복 거래·계좌·이체 / 결제수단 커스텀, 전체 기간 검색, 연간 리포트 / PWA·오프라인 설치 / IndexedDB 저장소(용량 한계 해소).
