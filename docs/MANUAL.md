## 1. 준비물

| 항목 | 요구 사항 |
| --- | --- |
| Node.js | **20.19 이상** (또는 22.12 이상). 이 프로젝트는 Node 24에서 개발·검증했습니다. |
| npm | Node.js에 포함(11에서 검증) |
| 브라우저 | 최신 Chrome, Edge, Firefox, Safari |
| 운영체제 | Windows, macOS, Linux (Windows 11에서 개발·검증) |

버전 확인(터미널·PowerShell 모두 동일):

```bash
node -v    # v20.19.0 이상이어야 합니다
npm -v
```

Node.js가 없거나 버전이 낮으면 <https://nodejs.org> 에서 LTS 버전을 설치하세요.

## 2. 설치

프로젝트 폴더(`가계부`)에서 한 번만 실행합니다.

```bash
cd C:\Users\User\Desktop\가계부     # 프로젝트 폴더로 이동 (경로는 본인 환경에 맞게)
npm install                          # 의존성 설치 (인터넷 필요, 1~2분)
```

- 설치가 끝나면 `node_modules` 폴더가 생깁니다. 이 폴더는 직접 건드리지 않습니다.
- **E2E 테스트를 돌릴 때만** 브라우저를 추가로 설치합니다(앱을 쓰기만 한다면 필요 없음):

```bash
npx playwright install chromium firefox webkit
```

## 3. 실행 방법

세 가지 방법이 있습니다. **그냥 써 보려면 3-A**, **실제로 계속 쓰려면 3-C(배포)** 를 권장합니다.

### 3-A. 개발 서버 (가장 간단, 소스를 고치며 확인할 때)

```bash
npm run dev
```

터미널에 다음과 같이 나옵니다.

```
  VITE v8.x  ready in ... ms
  ➜  Local:   http://localhost:5173/
```

브라우저에서 **<http://localhost:5173>** 을 엽니다. 종료는 터미널에서 `Ctrl + C`.

| 상황 | 방법 |
| --- | --- |
| 포트 5173이 이미 사용 중 | `npm run dev -- --port 3000` (원하는 번호로) |
| 같은 와이파이의 **휴대폰·다른 PC에서 접속** | `npm run dev -- --host` 후 터미널에 나오는 `Network: http://192.168.x.x:5173` 주소로 접속. Windows 방화벽 허용 창이 뜨면 "허용" |
| 브라우저를 자동으로 열기 | `npm run dev -- --open` |

> 개발 서버에서만 `http://localhost:5173/dev/components` (컴포넌트 쇼케이스)를 볼 수 있습니다. 배포본에는 없습니다.

### 3-B. 프로덕션 빌드 미리보기 (실제 배포본과 똑같이 확인)

```bash
npm run build      # 타입 검사 + 빌드 → dist/ 폴더 생성
npm run preview    # http://localhost:4173 에서 dist를 서비스
```

- 개발 서버보다 빠르고, 실제 배포본과 같은 최소화된 코드로 동작합니다.
- 휴대폰 접속: `npm run preview -- --host`

### 3-C. 배포해서 계속 쓰기 (정적 호스팅)

이 앱은 **서버가 필요 없는 정적 사이트**입니다. `npm run build`로 만든 `dist/` 폴더를 정적 호스팅에 올리면 끝입니다. 환경 변수, 데이터베이스, API 키가 없습니다.

```
dist/
  index.html
  favicon.svg
  assets/
    index-xxxx.js     (약 99KB gzip)
    index-xxxx.css    (약 5KB gzip)
```

**반드시 지켜야 할 두 가지**

1. **주소창에 직접 입력한 경로(예: `/transactions`)나 새로고침도 `index.html`로 응답**해야 합니다(SPA 폴백). 설정하지 않으면 새로고침 시 404가 납니다. 아래 예시를 참고하세요.
2. **사이트 루트(`https://도메인/`)에 올립니다.** `https://도메인/가계부/` 같은 하위 경로 배포는 별도 설정(`vite.config.ts`의 `base`, 라우터 `basename`)이 필요해 이 버전에서는 지원하지 않습니다. 하위 도메인(`ledger.example.com`) 방식을 쓰세요.

**호스팅별 폴백 설정 예시**

| 호스팅 | 설정 |
| --- | --- |
| **Netlify** | `dist`에 `_redirects` 파일을 넣고 내용 한 줄: `/*  /index.html  200` (빌드 전 `public/_redirects`로 두면 자동 복사됨) |
| **Vercel** | 프로젝트 루트 `vercel.json`: `{ "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }` |
| **Nginx** | `location / { try_files $uri /index.html; }` |
| **Apache** | `.htaccess`: `RewriteEngine On` / `RewriteCond %{REQUEST_FILENAME} !-f` / `RewriteRule ^ /index.html [L]` |
| **GitHub Pages** | 사용자·조직 사이트(`사용자.github.io`)는 루트라 가능하지만 폴백이 없어 새로고침이 404입니다. `404.html`에 `index.html`을 복사하는 방식을 쓰거나 위의 다른 호스팅을 권장 |

> **`dist/index.html`을 파일로 직접 더블클릭해서 여는 방식(`file://`)은 동작하지 않습니다.** 반드시 `npm run preview`나 웹 서버를 거쳐야 합니다.

> **데이터는 접속 주소별로 따로 저장됩니다.** `http://localhost:5173`, `http://127.0.0.1:5173`, `http://localhost:4173`, 배포 주소는 **서로 다른 저장소**라 데이터가 공유되지 않습니다. 주소를 바꾸면 "데이터가 사라진 것처럼" 보이므로, 계속 쓸 주소를 정하고 5절의 백업·가져오기로 옮기세요.

## 4. 사용법

화면은 크게 **홈 / 내역 / 설정**(+ 설정 안의 **카테고리 관리**) 입니다. 모바일에서는 화면 아래 탭, 데스크톱에서는 위쪽 메뉴로 이동합니다. 첫 실행 시 기본 카테고리와 결제수단이 자동으로 준비됩니다.

### 4-1. 내역 추가

1. **홈** 또는 **내역** 화면에서 **"내역 추가"** 버튼을 누릅니다(모바일은 화면 오른쪽 아래 둥근 **+** 버튼).
2. 입력합니다.

| 항목 | 설명 |
| --- | --- |
| 유형 | **지출**(기본) / **수입**. 바꾸면 카테고리 목록이 그 유형의 것으로 바뀝니다. |
| 금액 | 1원 이상의 **정수**(최대 9,999,999,999원). 쉼표(`12,000`)를 써도 됩니다. 소수점·음수·0은 입력할 수 없습니다. |
| 날짜 | 기본은 오늘. 다른 달을 보는 중이면 그 달의 1일. |
| 카테고리 | 유형에 맞는 카테고리 중 선택 |
| 결제수단 | 현금, 체크카드, 신용카드, 계좌이체, 기타 |
| 메모 | 선택, 200자까지 |
| 태그 | 선택, 쉼표나 공백으로 구분(`외식, 회사`). 최대 10개, 개당 20자. 앞의 `#`은 자동으로 정리됩니다. |

3. **저장**. **금액만 입력해도** 오늘 날짜·첫 카테고리·현금으로 저장됩니다.
4. 입력이 잘못되면 해당 항목 아래에 빨간 안내가 나오고 그 칸으로 포커스가 이동합니다. 고치면 안내가 사라집니다.
5. 보고 있는 달과 다른 달의 날짜로 저장하면 알림에 "(2026년 9월에 기록됨)"처럼 표시됩니다.

### 4-2. 내역 수정·삭제

- **내역** 화면(또는 홈의 "최근 내역")에서 행을 누르면 수정 창이 열립니다. 값을 바꾸고 **저장**.
- 수정 창 왼쪽 아래 **삭제** → 확인 창에서 **삭제**. 삭제하면 되돌릴 수 없습니다.

### 4-3. 월 이동

- 홈과 내역 화면 위쪽의 **‹ 2026년 10월 ›** 로 이전·다음 달로 이동하고, **이번 달** 버튼으로 돌아옵니다.
- 홈과 내역 화면은 **같은 달**을 공유합니다(새로고침하면 이번 달로 돌아갑니다).

### 4-4. 홈 화면 읽는 법

| 영역 | 내용 |
| --- | --- |
| 수입 / 지출 / 잔액 | 선택한 달의 합계. 잔액 = 수입 − 지출(음수면 `-` 표시) |
| 카테고리별 지출 | 도넛 차트 + 목록(금액, 비율). 비율의 합은 항상 100.0%. 도넛 가운데는 그 달 지출 합계(예: `3만원`) |
| 최근 6개월 추이 | 선택한 달을 마지막으로 한 6개월의 수입(초록)·지출(분홍) 막대. **"표로 보기"** 를 누르면 월별 수입·지출·잔액이 표로 나옵니다. |
| 최근 내역 | 그 달의 최근 5건. **전체 보기**로 내역 화면 이동 |

### 4-5. 내역 화면: 검색·필터

- **검색**: 메모·태그·카테고리 이름에서 찾습니다. 대소문자 구분 없음, 띄어쓰기로 여러 단어를 쓰면 **모두 포함**된 것만 나옵니다(`식비 점심`). 태그는 `#회사`처럼 써도 됩니다.
- **필터**: 유형 / 카테고리 / 결제수단 / 태그를 골라 좁힙니다(모두 동시에 만족). 모바일에서는 **필터** 버튼을 눌러 펼칩니다. **필터 초기화**로 모두 해제.
- 결과 위에 `N건 · 수입 … · 지출 …` 합계가 나옵니다.
- 검색·필터는 **선택한 달 안에서만** 동작합니다(다른 달은 월 이동 후 검색).
- 한 달에 내역이 많으면 100건씩 보여 주고 **더 보기 (N건 남음)** 로 이어 봅니다.

### 4-6. 카테고리 관리

**설정 → 카테고리 관리**

- **지출 카테고리 추가 / 수입 카테고리 추가**: 이름(1~20자, 같은 유형 안에서 중복 불가)과 색(9색 중 선택)을 정합니다.
- **수정**: 이름·색 변경. 수정하면 기존 내역에도 반영됩니다.
- **삭제**
  - 쓰는 내역이 **없으면** 확인 후 바로 삭제됩니다.
  - 쓰는 내역이 **있으면** "옮길 카테고리"(같은 유형, 기본은 '기타')를 골라 **옮기고 삭제**합니다.
  - 유형별 **'기타'는 삭제할 수 없습니다**("삭제 불가" 표시).
- 각 카테고리 옆의 `N건`은 그 카테고리를 쓰는 전체 내역 수입니다.

### 4-7. 설정

| 항목 | 설명 |
| --- | --- |
| 테마 | 시스템 설정 따름 / 라이트 / 다크. 이 브라우저에 저장됩니다. |
| 저장 공간 | 사용률, 크기, 앞으로 더 저장할 수 있는 대략적인 건수(6절) |
| 백업 파일 내보내기 / 가져오기 | 5절 |
| 모든 데이터 초기화 | 모든 내역과 직접 만든 카테고리를 지우고 처음 상태로. **되돌릴 수 없으니 먼저 백업**하세요. 테마는 유지됩니다. |

### 4-8. 키보드·접근성

- 모든 기능을 키보드로 쓸 수 있습니다. 첫 `Tab`을 누르면 **"본문으로 건너뛰기"** 가 나타납니다.
- 창(내역 추가 등)은 `Esc`로 닫고, 닫으면 열었던 버튼으로 포커스가 돌아옵니다. 입력 칸에서 `Enter`는 저장입니다.
- 카테고리 색은 방향키(←→)로 고를 수 있습니다.
- 화면을 이동하면 페이지 제목으로 포커스가 이동해 스크린리더가 화면 전환을 읽어 줍니다.
- 수입·지출은 색뿐 아니라 `+`/`-` 부호와 글자로도 구분되며, 차트는 수치 텍스트와 표를 함께 제공합니다.

## 5. 데이터 저장·백업·이동

### 5-1. 데이터는 어디에 저장되나

- **이 브라우저의 localStorage**에만 저장됩니다. 서버로 전송되거나 외부 서비스가 쓰이지 않습니다.
- 저장 위치는 **브라우저 × 접속 주소** 단위입니다(Chrome과 Edge, `localhost`와 `127.0.0.1`은 서로 다른 저장소).
- 브라우저의 **"사이트 데이터/쿠키 삭제"** 를 하면 가계부 데이터도 사라집니다. 이 점이 가장 큰 위험이므로 **주기적으로 백업**하세요(월 1회 권장).

### 5-2. 백업 파일 내보내기

**설정 → 백업 파일 내보내기** → `가계부-백업-2026-10-27.json` 같은 파일이 내려받아집니다(브라우저 다운로드 폴더).

- 내역, 카테고리, 결제수단, 구성원이 모두 들어 있는 JSON 파일입니다(테마 제외). 메모 편집기로 열어 볼 수 있지만 **직접 수정하지는 마세요**(검증에서 거부될 수 있습니다).
- 개인 금융 정보가 들어 있으니 안전한 곳에 보관하고 공유하지 마세요.

### 5-3. 백업 파일 가져오기(복원)

**설정 → 백업 파일 가져오기 → 파일 선택**

1. 파일을 검증합니다. 실패하면 **이유와 문제 위치(최대 5개)** 가 표시되고 **현재 데이터는 바뀌지 않습니다.**
2. 성공하면 확인 창에 `현재 데이터(내역 N건…)` → `백업 파일의 데이터(내역 M건…)` 가 표시됩니다.
3. **바꾸기**를 누르면 현재 데이터가 **모두 백업으로 교체**됩니다(병합이 아님). 되돌릴 수 없으니 필요하면 먼저 현재 데이터를 내보내 두세요.
4. 파일은 10MB까지, 이 앱이 만든 백업만 가능합니다. 더 새로운 버전 앱의 파일은 거부됩니다.

### 5-4. 다른 PC·브라우저·주소로 데이터 옮기기

1. 원래 쓰던 곳에서 **백업 파일 내보내기**
2. 파일을 새 PC로 복사(USB, 클라우드, 메일 등)
3. 새 곳에서 앱을 열고 **백업 파일 가져오기**

### 5-5. 엑셀(`Raw data.xlsx`) 데이터에 대해

프로젝트 폴더의 `Raw data.xlsx`는 **앱이 읽지 않습니다**(엑셀·CSV 가져오기는 이번 버전 범위 밖이며 향후 확장). 개인 금융 데이터이므로 `.gitignore`로 git에서 제외되어 있습니다. 필요한 내역은 앱에서 직접 입력하세요.

## 6. 저장 공간·경고·복구

### 6-1. 저장 용량

브라우저가 주는 공간(약 5MB)이 상한입니다. 내역 1건이 약 260자를 쓰므로 대략 다음이 한계입니다.

| 브라우저 | 대략적인 한계 |
| --- | --- |
| Chrome, Edge, Firefox | 약 **2만 건** |
| Safari (iPhone·iPad의 모든 브라우저 포함) | 약 **1만 건** (한글을 2바이트로 세어 절반) |

월 100~300건이면 수 년을 쓸 수 있고, 월 1,000건이어도 1~2년입니다. **설정 → 저장 공간**에서 사용률을 확인하세요.

### 6-2. 경고 배너

| 표시 | 의미 | 할 일 |
| --- | --- | --- |
| "저장 공간이 부족해지고 있습니다 (82% 사용 중)" | 80% 이상 | 백업 파일을 내려받고, 오래된 내역 정리를 고려 (배너는 "닫기"로 숨길 수 있으나 새로고침하면 다시 나옵니다) |
| "저장 공간이 거의 가득 찼습니다" | 95% 이상 | 바로 백업 후 정리. 가득 차면 저장이 실패합니다 |
| 저장 중 "저장 공간이 부족합니다." 알림 | 실제로 가득 참 | 입력한 내용은 창에 그대로 남아 있습니다. 공간을 확보한 뒤 다시 저장하세요 |

> 용량이 문제가 되면 저장소를 IndexedDB 등으로 교체할 수 있게 설계되어 있습니다(향후 확장).

### 6-3. 화면 맨 위의 안내: "창을 닫으면 입력한 내용이 사라집니다"

브라우저가 저장소 사용을 막은 환경(시크릿/프라이빗 모드, 쿠키·사이트 데이터 차단 등)입니다. 이 경우 **이 창이 열려 있는 동안만** 데이터가 유지되고 새로고침·창 닫기 시 사라집니다. 이 안내는 닫을 수 없습니다.

- 일반 창으로 열거나 브라우저의 사이트 데이터 차단 설정을 풀면 정상 저장됩니다.
- 급하면 **설정 → 백업 파일 내보내기**로 파일을 받아 두었다가 나중에 가져오세요.

### 6-4. "저장된 데이터를 읽을 수 없습니다" (복구 화면)

저장된 데이터가 손상된 경우입니다(다른 도구가 값을 망가뜨렸거나 브라우저 문제 등). **기존 데이터는 지우지 않고 그대로 두었습니다.** 세 가지 중 고르세요.

1. **손상된 원본 데이터 저장** — 손상된 내용을 파일로 저장합니다(나중에 복구를 시도할 때 쓰도록). **다른 선택 전에 먼저** 해 두는 것을 권합니다.
2. **백업 파일로 복구** — 이전에 내려받은 백업 파일을 선택하면 그 데이터로 바뀌고 앱이 열립니다. 잘못된 파일이면 이유가 표시되고 손상된 원본이 유지됩니다.
3. **모든 데이터를 지우고 새로 시작** — 확인 후 처음 상태로 시작합니다. 되돌릴 수 없습니다.

### 6-5. "문제가 발생했습니다" 화면

화면을 그리는 중 예기치 못한 오류가 난 경우입니다. 저장된 데이터는 변경되지 않았습니다. **다시 불러오기**를 누르고, 같은 문제가 반복되면 **데이터 내려받기**로 먼저 파일을 받아 두세요.

### 6-6. 여러 탭

같은 브라우저에서 여러 탭을 열어도 한 탭에서 바꾼 내용이 다른 탭에 자동 반영됩니다. 다만 **다른 브라우저 창(Chrome과 Edge 등)이나 다른 주소**는 별개의 저장소입니다.

## 7. 문제 해결

### 설치·실행

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `npm install` 후 `vite` 관련 오류, "Unsupported engine" | Node 버전이 낮음 | `node -v` 확인 후 20.19 이상(권장 22 LTS/24)으로 업그레이드 |
| `'npm'은(는) 내부 또는 외부 명령...이 아닙니다` | Node.js 미설치/PATH 미등록 | Node.js 설치 후 터미널을 **새로 열기** |
| `Port 5173 is in use` | 이미 개발 서버가 실행 중이거나 다른 프로그램이 사용 | 기존 터미널에서 `Ctrl+C`, 또는 `npm run dev -- --port 3000`. 사용 중인 프로그램 확인(Windows): `netstat -ano \| findstr :5173` |
| 경로에 한글이 있어 오류가 날까 걱정 | — | 이 프로젝트는 한글 경로(`가계부`)에서 설치·빌드·테스트를 모두 검증했습니다 |
| `npm run build`가 타입 오류로 실패 | 소스를 수정하다 타입이 어긋남 | 오류 메시지의 파일·줄을 고치고 `npm run typecheck`로 확인 |
| 휴대폰에서 접속이 안 됨 | `--host` 미사용 또는 방화벽 | `npm run dev -- --host`, 같은 와이파이인지 확인, Windows 방화벽에서 Node.js 허용 |

### 화면·데이터

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| **새로고침하면 404** 또는 빈 화면(배포 후) | SPA 폴백 미설정 | 3-C의 폴백 설정 적용 |
| 하위 경로(`/가계부/`)에 배포했더니 흰 화면 | 하위 경로 미지원 | 루트 또는 하위 도메인에 배포 |
| **데이터가 사라졌어요** | ① 접속 주소/포트가 바뀜 ② 다른 브라우저 ③ 사이트 데이터 삭제 ④ 시크릿 모드 | ①② 원래 주소·브라우저로 접속해 백업→새 곳에서 가져오기 ③ 백업 파일이 있으면 복원 ④ 6-3 참고 |

| 내역이 목록에 안 보임 | 다른 달에 저장됨(날짜 확인), 또는 검색·필터가 걸려 있음 | 월 이동, **필터 초기화** |
| 요일·날짜가 하루 어긋남 | — | 날짜는 시간대 변환 없이 입력한 그대로(로컬 날짜) 저장·표시합니다. 기기의 날짜를 확인하세요 |
| "저장 공간이 부족합니다" | 6-2 | 백업 후 정리 |
| 백업 가져오기: "JSON 형식이 올바르지 않습니다." | JSON이 아니거나 편집 중 깨짐 | 이 앱이 내보낸 원본 파일 사용 |
| 백업 가져오기: "더 새로운 버전의 앱에서 만든 데이터" | 앱 버전이 낮음 | 앱을 최신 버전으로 |
| 백업 가져오기: "데이터 검증에 실패했습니다" + 목록 | 내용이 규칙에 어긋남(없는 카테고리 참조, 잘못된 금액·날짜 등) | 표시된 위치(`transactions[3]` 등)를 확인. 원본 파일을 다시 내보내 쓰세요 |

### 데이터를 직접 초기화/확인하고 싶을 때 (개발자 도구)

브라우저 `F12` → **Application(애플리케이션) → Local Storage → 접속 주소**에서 키 `ledger.data`(데이터)와 `ledger.theme`(테마)를 볼 수 있습니다. 가능하면 앱의 **설정 → 모든 데이터 초기화**를 쓰세요.

## 8. 테스트 실행 (개발자)

| 명령 | 내용 | 대략 시간 |
| --- | --- | --- |
| `npm test` | 단위·컴포넌트 테스트(491건) | 약 15초 |
| `npm run test:coverage` | 커버리지 + 기준 강제(전체 85%, domain·storage 95/분기 90) | 약 30초 |
| `npm run test:e2e:chromium` | Chromium(데스크톱·모바일) 전체 E2E | 약 2분 |
| `npm run test:e2e:cross` | Firefox·WebKit·iPhone 핵심 흐름 | 약 1분 |
| `npm run test:e2e` | 위 E2E 전체(개발 서버 자동 기동) | 약 3분 |
| `npm run test:a11y` | 접근성(axe) + 키보드·리플로우 | 약 1분 |
| `npm run test:e2e:preview` | 프로덕션 빌드에서 핵심 흐름 | 약 30초 |
| `npm run check:bundle` | 번들 크기 예산(gzip JS 120KB, CSS 15KB) — 먼저 `npm run build` | 즉시 |
| **`npm run test:all`** | 타입 → 린트 → 커버리지 → 빌드 → 번들 → E2E → 프로덕션 E2E **전부** | 약 5~7분 |

자주 쓰는 형태:

```bash
npx vitest run src/domain/money.test.ts            # 파일 하나만
npx vitest run -t "한도"                            # 이름으로 선택
npx playwright test tests/e2e/months.spec.ts --project=desktop   # E2E 파일 하나
npx playwright test --ui                            # 인터랙티브 UI 모드(디버깅)
npx playwright show-report                          # 마지막 HTML 리포트
```

- E2E 실행 전 `npx playwright install chromium firefox webkit`을 한 번 해야 합니다.
- E2E가 서버를 자동으로 띄웁니다(`127.0.0.1:5173`). 이미 같은 포트에서 개발 서버가 돌아가고 있으면 그것을 재사용합니다.
- **워커 수를 컴퓨터 코어 수 이상으로 올리지 마세요**(과부하로 Firefox/WebKit이 시간 초과할 수 있음).
- 스크린샷은 `test-results/screenshots/`에 저장됩니다(실행할 때마다 새로 만들어짐).
- 테스트 작성 규칙·요구 추적표·변이 점검은 `docs/TESTING.md`.
