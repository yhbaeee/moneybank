# 가계부 앱 개발 계획 (DEVELOPMENT_PLAN)

- 기준 문서: `docs/PRD.md` v1.0
- 진행 원칙: **한 번에 한 단계만** 구현 → 실행 → 테스트 → 결과 보고 → 사용자 승인 → 다음 단계
- 각 단계 완료 시 `단계 완료 보고` 형식으로 보고하고, 승인 후 git 커밋한다. 승인 전에는 다음 단계 코드를 작성하지 않는다.
- 공통 검증(모든 단계): `tsc` 타입 검사, ESLint, Vitest, (해당 시) Playwright 실행 후 결과 보고
- 문제 발견 시 `docs/ISSUES.md`에 기록하고 해결 후 관련 테스트를 재실행한다.

## 기술 스택 및 구조 방침 (PRD 기본안 확정)

| 영역 | 선택 | 비고 |
| --- | --- | --- |
| 빌드/프레임워크 | React 18+ · TypeScript(strict) · Vite | |
| 스타일 | Tailwind CSS | 다크 모드는 `class` 전략 + CSS 변수 토큰 |
| 라우팅 | React Router | 화면 5개, 최소 사용 |
| 상태관리 | React Context + 커스텀 훅 (외부 라이브러리 없음) | 필요 시에만 재검토 |
| 차트 | 경량 SVG 직접 구현 또는 Recharts | 7단계 시작 시 번들 크기·접근성 기준으로 최종 결정 |
| 테스트 | Vitest + React Testing Library, Playwright | E2E는 `tests/e2e/` |
| 저장소 | `TransactionRepository` 등 인터페이스 + localStorage 구현 | 추후 SQLite/Supabase 구현체로 교체 |

### 예상 폴더 구조 (1~3단계에서 확정)
```
src/
  app/            라우팅, 프로바이더, 레이아웃
  components/     공통 UI 컴포넌트
  features/
    transactions/ 폼, 목록, 훅
    summary/      요약, 차트
    categories/   카테고리 관리
    settings/     백업, 테마
  domain/         타입, 순수 함수(금액·날짜·집계)  ← UI/저장소 의존 없음
  storage/        저장소 인터페이스 + localStorage 구현 + 마이그레이션
tests/e2e/        Playwright
docs/             PRD, 계획, ISSUES
```

## 단계 1. 프로젝트 초기화 및 개발 환경 구성

- **목표**: 빌드·타입·린트·테스트 도구가 모두 동작하는 빈 앱 골격
- **생성/수정 파일**: `package.json`, `vite.config.ts`, `tsconfig*.json`, `eslint` 설정, `tailwind`/`postcss` 설정, `vitest` 설정, `playwright.config.ts`, `src/main.tsx`, `src/app/App.tsx`, `.gitignore`, `.prettierrc`(선택), `tests/e2e/smoke.spec.ts`, npm scripts
- **구현 기능**: Vite+React+TS 생성, Tailwind 적용, Vitest·RTL 설정, Playwright 설치(브라우저 포함) 및 dev 서버 자동 기동 설정, 스크립트(`dev`, `build`, `typecheck`, `lint`, `test`, `test:e2e`)
- **완료 조건**: 모든 스크립트가 에러 없이 실행되고, "가계부" 제목이 표시되는 스모크 화면이 뜬다.
- **검증 방법**: `npm run typecheck && lint && test && build`, `npm run test:e2e`
- **Playwright 시나리오**: 앱 첫 진입 시 페이지 제목/헤더가 정상 표시
- **예상 리스크**: 한글 경로(`가계부`)로 인한 도구 오류, Node 24와 의존성 호환성, Playwright 브라우저 다운로드 실패
- **승인 포인트**: 폴더 구조, 의존성 목록, 스크립트 명령 확인

## 단계 2. 디자인 시스템, 레이아웃, 공통 컴포넌트

- **목표**: 이후 화면이 재사용할 UI 기반 확립(라이트/다크 포함)
- **생성/수정 파일**: `tailwind` 테마 토큰, `src/components/*`(Button, Input, Select, Modal/Sheet, Card, Badge, EmptyState, ConfirmDialog, Toast), `src/app/Layout`, 내비게이션(모바일 하단 탭/데스크톱 내비), 라우트 5개 빈 화면, 테마 토글, `docs/` 컴포넌트 가이드 일부
- **구현 기능**: 색상·타이포·간격 토큰, 다크 모드(시스템+수동, 새로고침 시 유지), 반응형 레이아웃, 접근 가능한 공통 컴포넌트
- **완료 조건**: 5개 화면 간 이동이 가능하고 라이트/다크에서 모두 정상 표시, 키보드 조작 가능
- **검증 방법**: 컴포넌트 단위 테스트, 타입/린트, 수동 스크린샷 검토
- **Playwright 시나리오**: 화면 간 내비게이션, 테마 전환 및 새로고침 후 유지, 모바일(390px)·데스크톱 레이아웃 스크린샷
- **예상 리스크**: 다크 모드 색 대비 부족, 모달 포커스 트랩 구현 누락
- **승인 포인트**: 디자인 톤(색상·컴포넌트 모양), 내비게이션 구성

## 단계 3. 데이터 모델, 타입, 저장소 계층

- **목표**: UI와 분리된 도메인 타입, 순수 함수, 저장소 추상화 완성
- **생성/수정 파일**: `src/domain/types.ts`, `money.ts`(금액 검증·포맷), `date.ts`(로컬 날짜·월 경계), `defaults.ts`(기본 카테고리·결제수단), `src/storage/repository.ts`(인터페이스), `localStorageRepository.ts`, `migrations.ts`, `backup.ts`(JSON 스키마 검증), 각 단위 테스트
- **구현 기능**: PRD 데이터 모델 타입, 금액/날짜 유틸, 저장소 CRUD, 최초 실행 시 기본 데이터 시드, 스키마 버전·마이그레이션 골격, 손상 데이터·저장 실패 처리
- **완료 조건**: 저장소 인터페이스를 통한 CRUD와 시드가 테스트로 검증, 월 경계·윤년·정수 금액 케이스 통과
- **검증 방법**: Vitest 단위 테스트(경계값 중심), 타입 검사
- **Playwright 시나리오**: 최초 진입 시 기본 데이터가 시드되고 새로고침 후에도 중복 시드되지 않음(간단 확인)
- **예상 리스크**: 날짜 타임존 버그, 스키마 설계 변경 시 재작업
- **승인 포인트**: 타입/인터페이스 정의, 저장 키 및 스키마 구조

## 단계 4. 거래 내역 CRUD

- **목표**: 내역 등록·수정·삭제가 end-to-end로 동작
- **생성/수정 파일**: `src/features/transactions/*`(TransactionForm, TransactionList, 훅, 검증), Context/프로바이더, 폼 검증 로직, 단위·E2E 테스트
- **구현 기능**: 지출/수입 토글, 금액·날짜·카테고리·결제수단·메모·태그 입력, 태그 정규화, 인라인 검증 메시지, 날짜별 그룹 목록, 수정, 삭제 확인
- **완료 조건**: 등록/수정/삭제가 목록에 즉시 반영되고 새로고침 후에도 유지, 잘못된 입력은 저장되지 않음
- **검증 방법**: 검증 함수·폼 컴포넌트 단위 테스트, 훅 테스트
- **Playwright 시나리오**: 지출 추가, 수입 추가, 입력값 검증(빈 금액·0·소수·음수), 수정, 삭제(확인/취소), 새로고침 후 유지
- **예상 리스크**: 금액 입력 UX(쉼표·IME), 한글 입력 조합 문제, 폼 상태 복잡도
- **승인 포인트**: 입력 폼 UX, 목록 표시 방식

## 단계 5. 월별 요약 및 카테고리 집계

- **목표**: 선택 월의 수입·지출·잔액과 카테고리별 집계를 정확히 표시
- **생성/수정 파일**: `src/domain/summary.ts`(순수 집계 함수), `src/features/summary/*`(SummaryCards, CategoryBreakdown), 홈 화면 구성, 테스트
- **구현 기능**: 월별 합계·잔액(음수 구분), 지출 카테고리별 금액·비율(합 100% 보정 규칙), 거래 변경 시 즉시 갱신
- **완료 조건**: 집계 결과가 입력 데이터와 정확히 일치, 거래가 없을 때 빈 상태 처리
- **검증 방법**: 집계 함수 단위 테스트(월 경계·비율 반올림), 컴포넌트 테스트
- **Playwright 시나리오**: 여러 건 입력 후 요약 수치 확인, 수정·삭제 후 요약 갱신, 카테고리별 집계 표시
- **예상 리스크**: 비율 반올림 오차, 월 경계 누락
- **승인 포인트**: 홈 화면 정보 구성, 비율 반올림 규칙

## 단계 6. 필터, 검색, 월 이동

- **목표**: 월 단위 탐색과 내역 검색·필터
- **생성/수정 파일**: `src/features/transactions/filters/*`, 월 이동 컴포넌트, 선택 월 상태(URL 쿼리 또는 Context), `src/domain/filter.ts`, 테스트
- **구현 기능**: 이전/다음/이번 달 이동, 검색(메모·태그·카테고리명), 필터(유형·카테고리·결제수단·태그, AND), 필터 초기화, 결과 없음 상태, 선택 월·필터와 요약 연동
- **완료 조건**: 월을 이동하면 목록·요약이 해당 월 기준으로 바뀌고, 검색·필터가 조건대로 동작
- **검증 방법**: 필터 함수 단위 테스트, 월 이동 경계(연말·연초) 테스트
- **Playwright 시나리오**: 월 이동(연도 경계 포함), 검색, 복합 필터, 필터 초기화, 새로고침 시 동작
- **예상 리스크**: 월 상태 공유 방식 복잡도, 검색 성능
- **승인 포인트**: 필터 UI 배치, 월 상태를 URL에 둘지 여부

## 단계 10. 단위 테스트 및 Playwright E2E 테스트 보강

- **목표**: PRD 핵심 흐름 전체를 회귀 테스트로 고정하고 커버리지 공백 해소
- **생성/수정 파일**: `tests/e2e/*.spec.ts`(시나리오별), 테스트 헬퍼·픽스처, 단위 테스트 보강, 커버리지 설정
- **구현 기능**: 아래 필수 E2E 시나리오 전체 정비 — 첫 진입, 지출/수입 추가, 입력 검증, 수정, 삭제, 월 요약 갱신, 카테고리 집계, 검색/필터, 월 이동, 새로고침 유지, 모바일 레이아웃. 테스트 간 데이터 격리(localStorage 초기화)
- **완료 조건**: 단위·E2E 전부 통과, 불안정(flaky) 테스트 없음(연속 3회 실행), 도메인 로직 커버리지 목표 달성(예: 90%+)
- **검증 방법**: `npm run test -- --coverage`, `npm run test:e2e` 반복 실행
- **Playwright 시나리오**: 위 전체
- **예상 리스크**: 날짜 의존 테스트 불안정(시간 고정 필요), 느린 E2E
- **승인 포인트**: 테스트 커버리지 범위와 결과
